# AlphaTastic (the Hangman repo)

**Read "AlphaTastic on @tastic/shell" below first: where an older section here disagrees with it about the root, Home, routes, Stats, Profiles or Settings, it wins.** The older sections still describe the games themselves accurately.

An ad-free pack of word games (Expo/React Native): Hangman, plus prototypes of Word Search, Jumble and Cryptogram. Part of the `@rific`/`@tastic`/InfiniteToken app ecosystem. It depends on `@rific/auto-paper`, `@rific/feedback-press`, `@rific/focus-chain`, `@rific/gestures` (`SwipeToDismiss`, for swiping Pass & Play seats away; see "Pass & Play sessions"), `@rific/splash-gate`, `@rific/toaster`, `@rific/updater`, `react-native-sortables` (dragging Pass & Play seats into a new order, 2026-10-20; see "Pass & Play sessions" > The page), `@tastic/sprites` (the `./fireworks` subpath only, for the win-celebration burst; see `src/effects/FireworksCelebration.tsx`), `@tastic/hud` (the `./chrome` subpath only; see "Fleet chrome via `@tastic/hud/chrome`" below), and `@tastic/profile` (the fleet's player profiles, 0.16.2+: 0.16.1 added `OptionPickerOption`'s `color`, which the Single Player loadout's Difficulty rows use, and 0.16.2 tells a swatch renderer where it draws, so the chips stay flat; see "Players" below). `@tastic/sprites` was published as `@tastic/animations` until it was renamed; the old name is deprecated on npm, and Hangman switched on 2026-10-14 (the fireworks source is byte-identical). Still no Skia dependency: unlike the fleet's Skia-rendered games (BoxHockey, AirHockey, Snake), this app draws its gallows/word-reveal "modes" with `react-native-svg`, and `@tastic/sprites/fireworks` is itself SVG-based, so this app never depends on `@shopify/react-native-skia` at all. `@tastic/sprites` also has Skia-based subpaths (`./gravity`, `./shapes`, `./hockey`) that this app doesn't import; the package's subpaths keep each renderer's peer dependency scoped to only the apps that actually use it.

**Expo has changed.** Read the exact versioned docs at https://docs.expo.dev/versions/v58.0.0/ before writing any code - don't rely on general Expo knowledge, this app is on SDK 58 specifically (and expo-router 58: see "Routes and resume" below).

## Commands

```bash
npm run lint          # expo lint .
npm run fix            # expo lint . --fix
npm run font           # rebuild assets/fonts/AlphaSketch.otf, the title font
npm test               # Jest (88 suites, 1474 tests)
npm run test:watch     # Jest --watchAll
npm run typecheck      # tsc
npm run verify         # lint + test + typecheck
npm run doctor         # expo install --fix && expo-doctor
npm start              # Expo dev server
npm run client          # Expo dev server (dev client build)
npm run build:web       # verify, then the web export for games.infinitetoken.com/hangman/
```

Always run `npm run lint` before finishing any task. This is an app (`"private": true`, no publish scripts) - `verify` doesn't include a build step.

**Builds and OTA updates:** the `build` and `update` scripts are plain `eas build` and `eas update`, with profiles in `eas.json` (`development`, `preview`, `production`). Pass the profile through, e.g. `npm run build -- --profile preview` or `npm run update -- --branch production --environment production --message "..."`. Nothing in them runs `verify`, so run `npm run verify` first. An OTA update also bumps `otaVersion` in `src/constants/release.ts` (the version label players see), committed before publishing. They used to be `@rific/updater`'s `rific-updater-build`/`rific-updater-update` bins, which @rific/updater 0.7.0 removed; the package stays for its OTA update hook. `build:web` is the one exception: it chains `npm run verify &&` before the web export (see "Web on games.infinitetoken.com" below).

**A real regression, found and fixed as part of this migration: a manual mock under `src/__mocks__/` for a deep SUBPATH of a node_modules package is not reliably auto-applied the way a bare package-name mock is.** Every mock listed above for a *bare* package (`react-native-reanimated`, `expo-audio`, `redux-persist`, `@rific/scroll-view`, etc.) works with zero registration, matching this package's own documentation. But `2 of 30 suites` (`PackPuzzleList.test.tsx`, `PnpFlow.test.tsx`) started failing after the pure file-extraction pass, both on assertions sensitive to a react-native-paper `<Button icon='...'>`'s rendered text - instead of an empty icon slot, the raw MaterialCommunityIcons font glyph character showed up before the label. Confirmed directly, not guessed: a `console.warn` planted in the real (un-mocked) `@expo/vector-icons/build/MaterialCommunityIcons.js` and in react-native-paper's own compiled `MaterialCommunityIcon.js` fired during a failing test with a same-shaped mock file already sitting under `src/__mocks__/` for both, and did *not* fire once each was registered - and, separately, that `import * as RNPaper from 'react-native-paper'` (ESM, in real app/test code, transformed by `babel-preset-expo`) resolves to `react-native-paper/src/index.tsx`, while a plain `require.resolve('react-native-paper')` call resolves to `lib/commonjs/index.js` instead - two different real files, confirmed by the same technique. This app's own pre-migration `jest.setup.ts` never hit this, because it always registered every one of these subpaths with an explicit `jest.mock(path, factory)` call - the migration only moved the factory *bodies* out, and dropped the registration itself along with them. Fixed by keeping an explicit, no-factory `jest.mock('specifier')` call in `jest.setup.cjs` for every subpath mock (bare-package mocks still need none), so Jest is told to use the adjacent `src/__mocks__/` file rather than relying on auto-discovery. One further gap surfaced in the process and needed a fresh mock, not just a registration: `Theme.tsx` imports `@expo/vector-icons/MaterialCommunityIcons` (no `/build/`) directly to preload the icon font - a real module this app's own original `jest.setup.ts` never mocked either, but registering only the `/build/` subpath wasn't enough to stop *this* import from loading the real font-glyph component. That one is an inline factory in `jest.setup.cjs` rather than its own `src/__mocks__/` file, since a bare registration for it alone didn't reliably pick up an adjacent file either. **Flagged for Jay below** - this likely affects other already-migrated apps with subpath mocks (`redux-persist/integration/react`, `@expo/vector-icons/createIconSet`, etc.) that simply never had a test assertion sensitive enough to catch it.

**Migrating onto `@infinitetoken/tsconfig/expo` turned on `noUnusedLocals` for the first time**, surfacing 19 dead `import React from 'react'` statements (leftover from before the `react-jsx` transform made them unnecessary) across `App.tsx`, `src/__tests__/App.test.tsx`, `src/components/GameVisual.tsx`, `src/components/SketchWord.tsx`, and 15 of the `src/modes/*.tsx` visual-mode files - removed (three of them, `jenga.tsx`/`snowflakes.tsx`/`stars.tsx`, kept their `{ useState }` named import, only the default `React` import was dead). ## Testing

- Framework: Jest (`@infinitetoken/jest-config/expo`, `jest-expo` preset)
- Tests live in `src/__tests__/`, mirroring the source subfolder structure (`components/`, `effects/`, `hooks/`, `utils/`)
- Native/Expo module mocks live in `src/__mocks__/`, one file per module (including several scoped subpaths) - a bare-package mock is picked up automatically, but every subpath mock needs its matching explicit `jest.mock('specifier')` call in `jest.setup.cjs` too (see Tooling above for why)
- `jest.setup.cjs` holds only genuine setup-file concerns: the explicit subpath-mock registrations, process-level error handlers, the `IS_REACT_ACT_ENVIRONMENT` flag, and this app's own Animated-JS-driver-forcing + `NativeAnimatedModule` synchronous-callback patches. The RAF polyfills and no-factory `NativeAnimatedHelper` automock it used to carry were removed on 2026-10-02 as no-ops: `@react-native/jest-preset`'s own setup (pulled in by `jest-expo`, and run before this file) already defines `requestAnimationFrame`/`cancelAnimationFrame`, so the `typeof ... === 'undefined'` guards never fired, and `react-native/Libraries/Animated/NativeAnimatedHelper` doesn't exist in RN 0.86 (it moved to `src/private/animated/`), so that `jest.mock()` call always threw into a bare `catch` and never applied
- RNTL 14's `render`/`rerender`/`unmount`/`fireEvent` are all async: always `await` them. `render` only queues its tree for the automatic afterEach unmount once its own promise resolves, so an un-awaited `render` (App.test.tsx did this until 2026-10-13) leaves the whole app mounted, timers still firing, after the file's Jest environment is torn down.
- Anything that reads the active player (stats, rounds, puzzle unlocks, art, difficulty, packs, colors) needs the app `store`; reset `activePlayer`, `playerSettings`, `playerTheme` and `profiles` (`profilesActions.setAll([])`) (and `round`, `achievements`) in `beforeEach`, and give a hand-built test store the `activePlayer` reducer. Choose Packs' tests (and its pages') wrap in the store and `CatalogProvider`. A profile made active before `Providers` mounts has to be on the roster, or `ProfilesProvider`'s launch reconcile forgets it and the guest plays. At the Pass & Play table (its page and games) a guest seat plays as its own guest, `guestSeatKey(seatId)`, never `GUEST_PLAYER_KEY`: seed a table guest's picks, colors and rounds under the seat's key, and the active player reads `{ profileId: null, seatId }`. Under Jest there is no shared roster (no App Group module, not the web), so the roster is the store's own copy; `useProfiles.test.tsx` fakes the shared store at its native end (expo-modules-core's `TasticProfile` module) to run the package's real sync. @tastic/profile's pickers only show their popover once hud's `useAutoAlign` has measured the trigger, and the jest preset's View never answers `measureInWindow`, so a test that opens one spies `View.prototype.measureInWindow` to call back (see `LoadoutScreen.test.tsx`).
- A test that renders auto-paper's `Provider` passes `statusBar={false}`, as `Theme.tsx` does. Otherwise it renders React Native's own `StatusBar`, whose update is a `setImmediate`. Under fake timers on Node 22 (what CI runs), every later `render` in that file then never settles: the test hits its 5s timeout, and so does every one after it. Node 26 doesn't hang, so it passed locally (fixed 2026-10-20, after the v1.0.1 Deploy and CI runs failed in HeroTitle and SettingsDialog). Before trusting a local pass on a timing-sensitive suite, run it under Node 22 too (`npx -y node@22 node_modules/.bin/jest <file>`).
- `src/__mocks__/react-native-reanimated.ts` animates nothing: `Animated.View` is React Native's own View (so a test reads `entering`, `exiting` and `layout` straight off it), the layout animation presets (`FadeIn`, `ZoomIn`, `LinearTransition`, ...) are builders whose every modifier hands back the same builder, `LayoutAnimationConfig` renders its children, `withTiming` hands back its target, and `useReducedMotion` is a `jest.fn` returning false. A test that turns Reduce Motion on puts it back after (`jest.clearAllMocks` keeps a `mockReturnValue`). To watch `withTiming`, mock the module with a factory over the mock file (`useEasedValue.test.ts`): a spy on the imported module doesn't reach the hook's own import.
- Nothing in an always-mounted subtree (Choose Packs and its pages stay mounted while away, and Home and the loadout stay mounted under the screens pushed over them) may run timers while hidden. ModePickerDrawer's card demo loop used to, so every test rendering the old Main or App fed React real-timer updates for as long as the tree lived. On a slow CI runner that turned one test hitting the 5s timeout into a whole file of timed-out tests and timed-out RNTL cleanup hooks, and CI run 37263959211 then hung until GitHub's 6-hour limit (fixed 2026-10-13: the loop pauses while the drawer is closed).

## OS portrait lock (2026-10-08)

Hangman is portrait-only and, unlike the @tastic games, draws no rotation of its own; nothing here lays out for a landscape window. It still takes `@tastic/core` for its Expo config plugin (`["@tastic/core", { "drawsRotation": false }]` in `app.json`'s `plugins`); its JS only arrives indirectly, through `@tastic/hud/chrome`, and nothing here mounts its `OrientationProvider` or draws rotation. The plugin owns the native lock: `orientation: "portrait"`; `ios.requireFullScreen` plus an iPad list of Portrait and UpsideDown (without it Expo forces all four iPad orientations and an iPad turned sideways got this portrait layout in a landscape window; the cost is Split View, Slide Over and Stage Manager); and `android:appCategory="game"` (Android 16 and later ignore the portrait lock on tablets and unfolded foldables, except for games). `drawsRotation: false` is what keeps UpsideDown on iPad: with no app-drawn rotation, iOS's own 180 flip is correct here, while the @tastic games list Portrait only because they draw the 180 themselves. Don't set any of those by hand. Check with `npx expo config --type introspect`; it only takes effect in a new native build (`ios/` and `android/` here are gitignored prebuild output, regenerated by `npx expo prebuild`).

## Icons and splash (2026-10-13)

Seven games (AirHockey, BoxHockey, Hangman, LightCycles, Pong, Snake, Solitaire) and Expo-Starter use the same four files, `assets/images/icon-light.png`, `icon-dark.png`, `splash-light.png` and `splash-dark.png`, and the same `app.json` config. The icons are opaque 1024px squares on `#FAFAFA` (light) and `#050505` (dark). Each splash is its icon's art on a transparent background. The `expo-splash-screen` plugin paints the same two colors behind it, at `imageWidth` 200. `expo.icon` is `icon-dark.png`, `web.favicon` is `splash-dark.png`, `ios.icon` is the dark/light pair, and there is no Android `adaptiveIcon` (Android uses `expo.icon`). The favicon is the transparent splash art, not the opaque icon, because it looks better in a browser tab (2026-10-16), so `splash-dark.png` has to read on both light and dark tabs. Snake is the only game whose light and dark art differ (its body and head fill). The other games keep two identical splash files so the config is the same everywhere. Icon and splash changes only take effect in a new native build.

## Players (2026-10-17)

Everything belongs to a player (Jay, 2026-10-17: his kids play a puzzle, then hand him the device): stats and achievements, unlocked puzzles, the waiting solo round, colors, art, difficulty and pack selection. Keyboard, sound and haptics stay device-wide. A player is a profile from the fleet's shared roster (`@tastic/profile` 0.16+, the same profiles as every @tastic game) or the guest. ## Word Search prototype (2026-11-18)

Word Search is the pack's first new game, the first test of whether grids themed by the puzzle packs are fun: `/play/wordsearch` (`src/games/puzzleGames.tsx` over `WordSearchScreen`), from its card on Home and its setup page. It's a prototype: nothing is saved (leaving drops the puzzle, and `useActiveGame` doesn't know it), and it adds to no stats, achievements or unlocked puzzles. Pass & Play doesn't reach it, and a screen reader can read the word list but can't play the grid.

- **The puzzle** (`src/utils/wordSearch.ts`, pure, every random step through an `rng` argument): `drawWordSearch` takes one of the active player's selected packs (every pack with enough answers equally likely, as a Hangman draw), so a grid has one theme and the header is the pack's name. Its settings set the grid: Small is 10x10 with 8 words, Medium 12x12 with 10, Large 14x14 with 14; Straight runs across and down, Diagonal adds both forward diagonals, Backward uses all eight directions. Answers lose their spaces, need 4 letters and must fit the grid, and one word never sits inside another. Filler letters are half from the hidden words, and `cleanFiller` rerolls any that spell a blocked word, in any direction, since children play this.
- **The drag** (`WordSearchGrid`): a Gesture Handler pan on the JS thread, snapped to the nearest of eight straight lines (`snapWordSearchSelection`). A selection is matched by its letters, read from either end, so a copy the filler spelled counts too. Two traps, both pinned by `WordSearchGrid.test.tsx`: the worklets Babel plugin copies the variables a gesture callback closes over, even with `runOnJS(true)`, so shared drag state has to live in an object; and a rebuilt gesture has to be attached again, so a fast next drag could be lost (seen in the web preview), which is why the gesture stays the same and is handed the latest `onSelect` in a layout effect.
- **Drawing:** the letters are the board's sketch glyphs, the whole grid as one SVG path (`lettersPath`, using `sketchLetter`'s `catmullRomPath`), with the found and dragged bands under them in the theme's colors.
- **Checked** in the web preview (2026-11-18, 375x667 and 1200x800, light and dark, sound muted): drags across, down, diagonally and backward, a wrong selection, ten fast drags in a row, the fireworks, the solved card and Next Puzzle. Not yet on a device.

## Keep Awake (2026-10-17)

Jay chose to give Hangman Keep Awake (keep the screen from locking during a round: the OS auto-lock only counts touches, so a long think on a guess, or a Pass & Play hand-over, can lock a release build). `/game` (`src/app/game.tsx`'s `GameRoute`) calls `@rific/core`'s `useKeepAwake('game')`, released on unmount, unless the player turns off the Keep Awake row in Settings (default on, read live so the toggle applies mid-round). - **The setting is core's:** `keepAwakeReducer` is mounted as `keepAwake` in `store.ts` and listed in the persist whitelist, and `Providers.tsx`'s `KeepAwakeBridge` (`initialValue` from the slice, `onChange` dispatching `keepAwakeActions.initialize`, the same bridge as the other games) mounts core's `KeepAwakeProvider` with `expoKeepAwake={ExpoKeepAwake}` (`import * as ExpoKeepAwake from 'expo-keep-awake'`), directly inside PersistGate so it is above every Portal.Host. - The row is `@tastic/hud`'s (0.23.0+): `BaseSettingsDialog` reads core's setting itself, with no props, and shows the row (caption "Stop auto-lock mid-match") only when `useExpoKeepAwake()` returns a module and the device is touch-first (native and touch-first browsers). Needs `@rific/core` 0.4.0+.
- `expo-keep-awake` is a direct dependency (`~58.0.3`, via `npx expo install`). It was already in native builds as a dependency of `expo`, so no new native build is needed.

## The 2026-11-13 puzzle audit

Before the App Store submission every answer in the 58 packs was read (six reviewers, every flag matched back to the data by script). The results, and Jay's per-answer choices, are on a private artifact, https://claude.ai/artifact/R5kCb5LRJgUBfzHsp6K4ng: 1,124 flagged answers at first (not 4+, unguessable, wrong pack, broken, near-duplicate), 1,022 left after 2026-11-14 and 871 after 2026-11-15 (the applied cuts are listed under the page's Already fixed, so every row left defaults to Keep), each Keep, Fix or Cut, saved in its db collection `decisions` (one document per pack key, `choices: { puzzleId: 'cut' | 'keep' | 'fix' }`; a row with none takes the page's default). Jay took the page's defaults on 2026-11-15 (see Default cuts, below); the page's db still holds no choices of his, and any he saves later goes in the same way. Still open: packs whose contents don't match their names (Empires, US Politicians, Travel; Countries, Greek & Roman Gods and Airplanes were settled, below), and the hint upgrades (Wikipedia's short descriptions for the 49 packs with no clue, and a director or star for Movies and TV from the same Wikidata pull). IMDb's terms and the Phrases source were settled by replacing both (below), and the most telling genre came with it.

Fixed in Hangman-Scrapers first and then published here (19,475 puzzles at the time), all without a call except Countries and Gods & Heroes:

- **Word breaks:** `normalizePhrase` (and the scraper's `normalize()` and `customPackExport.ts`, through its `breakWords`) breaks at a semicolon, colon, plus, middle dot, ellipsis, minus sign, two or more dots, and a dot between a letter and a word of two or more letters (initials stay together: E.T. is ET), and reads × as X. Twelve answers had played as one fused word (OOPSI DID IT AGAIN, STEINSGATE, WALLE, DGRAY MAN). Pinned in `puzzlePicker.test.ts`.
- **Numbers:** the scraper turns superscript digits and fractions into digits, so its guessable check drops them: Alien³ (which played as a second ALIEN), [Rec]² and Ranma ½ are gone.
- **Repeated answers:** a pack keeps only the best-known of the puzzles that play the same blanks (`buildPuzzleCatalog`'s `dropRepeatedAnswers`, by Wikipedia reads (`views`) or Last.fm listeners): mostly remakes, 224 movies and 36 shows since the Wikidata rebuild. - **Source counts:** publishing drops Wikipedia's `views` and Last.fm's `listeners` and `playcount` from the app's copy, since nothing here reads them. The scraper keeps them for filtering and the repeated-answer pick.
- **Ready renames** (2026-11-14): the audit page's 32 Fix rows (and Quaoar and Sedna, below), applied through Hangman-Scrapers' `scripts/puzzleOverrides.json` (`puzzleOverrides.ts`, applied first in `buildPuzzleCatalog`, keyed by pack file and the scraped answer, matched by normalized answer like the blocklist; a renamed puzzle keeps its id): the nine First Ladies without the quoted nickname (Pat Nixon, Lady Bird Johnson), Magic Tree House, Wii Fit, Star Wars: Episode III Revenge of the Sith, the two cut-off proverbs and Peter Piper in full, Baby doll, Skateboard and Stick without "The", Ford Taurus, Washington, D.C., Dine N Dash, The Whitest Kids U Know, three Phrases entries refiled under the right category, JAY-Z's name in two song hints, and Pluto, Ceres, Eris, Haumea and Makemake as Dwarf Planet (Space's hint). Those rows, and the Countries and Gods & Heroes ones, are off the audit page now.

## Metro cache key (2026-11-16)

`metro.config.cjs` sets Metro's `cacheVersion` to a hash of this app's public config (`getConfig(__dirname, { isPublicConfig: true })`). It's the file's only job, so it isn't boilerplate. It's `.cjs` because this package is `"type": "module"`, where a `.js` config would be an ES module and export nothing. The shared ESLint preset lints `.cjs` files without CommonJS's globals, so it opens with `/* global __dirname */`. On the web, Expo writes the app config into expo-constants as it bundles (what `Constants.expoConfig` reads, the web tab title included), but Metro's cache key leaves the config out, and every app on this Mac shares one cache folder (`$TMPDIR/metro-cache`). So an app on the same package versions as another was served the other's config: Swirlio's dev server showed `<title>Labyrinth</title>` on 2026-11-16, and on 2026-10-14 every exported title read "LightCycles". The key keeps this app's cache apart from the others and refreshes it whenever the config changes (a version bump included), at the cost of one cold bundle after each change.

- The same lines are in HexFleet, Lumber, CardTastic, DuelTastic, PuckTastic, Hangman (`metro.config.cjs`) and Swirlio. Drop them once Expo puts the app config in its own cache key.
- Expo's fingerprint doesn't read Metro config, so this changes no runtime version and needs no native build.
- Checked in Swirlio: with Labyrinth's entries in the cache, its dev server got a key of its own and served its own title and config. In the other apps only loading the config was checked.
